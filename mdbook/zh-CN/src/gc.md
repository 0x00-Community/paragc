# 什么是垃圾收集器

程序要为数据分配内存：一个链表节点、一个字符串、一个对象。到某个时候这些数据不再需要了，内存应该拿去复用。总得有人决定
**什么时候**。

- 在 C 里由程序员决定：`malloc` 拿内存，`free` 还内存。还早了，程序会读到已经属于别人的内存（释放后使用）；忘了还，内存
  泄漏；还两次，分配器自己的账就乱了。
- 在 Rust 里，大部分数据由编译器决定：每个值有唯一的所有者，所有者离开作用域时值被丢弃。只要数据是一棵树，这就行得通。
  带环的图、没有明确所有者的共享数据，就要用 `Rc`/`Arc`（引用计数）或 arena，各有各的限制。
- **垃圾收集器**（GC）在运行时看着数据本身来决定。程序再也走不到的内存就是**垃圾**，收集器把它找出来复用。程序只管分配，
  从不释放。

程序被称为 **mutator**：在收集器看来，它做的事就是不停地改动（mutate）对象图。收集器是另一方，负责回收 mutator 再也用不到
的东西。

## 可达性

收集器不可能知道程序将来会用哪些对象，这在一般情况下不可判定。它用一个保守而安全的近似代替：**程序还能走到的对象就是活的**。

- **根**是程序直接读取的位置：各个栈上的局部变量、寄存器、全局变量；在 paragc 这样的库里，还有程序明确登记的 Handle（`ScopeGlobal`）。
- 从某个根出发有一串指针能走到的对象，是**可达的**。
- 其余的都是垃圾。没有任何指针链通向它，程序再也碰不到它，复用它的内存是安全的。

可达的对象也可能再也不会被用到。那块内存是 GC 修不了的泄漏，但永远不会导致崩溃。

## 两大家族：追踪与引用计数

| | 追踪 | 引用计数 |
| --- | --- | --- |
| 思路 | 时不时从根出发，沿每个指针走，标记走到的；其余是垃圾 | 每个对象数着指向自己的指针；数到 0 就是垃圾 |
| 工作量正比于 | 活数据（标记）和堆大小（清扫） | 指针写入的次数 |
| 环 | 自然能收 | 永远到不了 0：除非另有机制，否则泄漏 |
| 内存何时回来 | 下一次回收时 | 计数归零的那一刻 |
| 对 mutator 的代价 | 小（只有部分设计需要屏障） | 每次指针写入都要改两个计数 |

实际的收集器把两者混着用。CPython 用引用计数，再用追踪收环；paragc 所依照的 LXR 对老对象做引用计数，隔一段时间追踪一次。

## 追踪式收集器：垃圾怎么处理

标记之后，追踪式收集器有几种选择。

| 算法 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **标记-清扫** | 走一遍堆，把没标记的对象放进空闲链表 | 对象从不搬动 | 碎片；分配时要搜空闲链表 |
| **标记-压缩** | 把活对象滑到堆的一端挤在一起 | 无碎片；指针递增分配 | 要扫好几遍堆；每个指针都得更新 |
| **复制**（半区） | 追踪时把活对象复制到一个空的区，旧区整个变空 | 一遍完成，工作量只正比于活数据；指针递增分配 | 一半内存闲着；长寿对象被一遍遍复制 |
| **标记-区域**（Immix） | 以块里固定大小的行为单位释放内存；只有块很稀疏时才复制 | 在空闲行里指针递增分配；复制很少 | 一个对象可能让一行部分用不上 |

## 分配

- **空闲链表分配**按大小搜索空闲块链表：灵活但慢，还会产生碎片。
- **指针递增分配**（bump）只有一个指针和一个上限，把指针往前推：一次比较加一次加法。它需要连续的空闲空间，这正是压缩、复制、
  区域式收集器分配快的原因。
- **线程本地分配缓冲（TLAB）**：每个线程在自己的一段里递增分配，分配完全不需要同步。

## 收集器什么时候跑

| 方式 | 含义 |
| --- | --- |
| **全停（stop-the-world）** | 收集器工作时所有 mutator 线程都停下。最简单；这一停就是**停顿** |
| **并行** | 收集器在停顿中用多个线程。停顿变短，mutator 仍然停着 |
| **增量** | 收集器把工作切成小片，和 mutator 交替执行，一次一个线程 |
| **并发** | 收集器在别的线程上跑，mutator 同时继续运行 |

安全地停下 mutator 需要**安全点**：程序里每个线程的根都已知的位置。JVM 这样的运行时在循环回边和调用处轮询。paragc 不用
安全点：Rust 的借用检查器证明全停回收时没有 mutator 在堆里。

## 三色标记与屏障

Dijkstra 等人用三种颜色描述追踪：

- **白**：还没走到（一直是白的话就是垃圾）；
- **灰**：走到了，但它的指针还没扫；
- **黑**：走到了，也扫完了。

没有灰对象时标记结束。如果 mutator 在标记**期间**运行（增量或并发），它可能把一个对象藏起来：把指向白对象的指针存进一个
黑对象，再删掉另一条唯一的路径。收集器永远看不到它，会把一个活对象释放掉。**屏障**防止这种事。屏障是编译器或库在每次指针
写入（写屏障）或读取（读屏障）时执行的几条指令：

| 屏障 | 做什么 |
| --- | --- |
| **插入屏障**（Dijkstra） | 存指针时，把新目标标灰 |
| **删除屏障 / 开始时快照**（Yuasa） | 指针被覆盖时，把旧目标标灰。标记开始时可达的一切都能活下来 |
| **读屏障**（Baker、Brooks、load barrier） | 读出指针时，保证它指向被搬动对象的当前副本 |

标记期间分配的对象通常直接成为黑色（**黑分配**）。

## 分代

**弱分代假说**说：大多数对象死得早。**分代**收集器：

- 把堆分成年轻代（nursery）和一个或几个老年代；
- 年轻代收得勤、收得便宜（**minor** 或**年轻**回收），整个堆很少收（**major** 或**完整**回收）；
- 熬过几次年轻回收的对象搬进老年代（**晋升**）。

年轻回收不追踪老年代，所以必须知道老对象指向年轻对象的指针。写屏障把它们记在**记忆集**里，或者在**卡表**里把所在的那一小块
内存标脏。

## 精确还是保守

- **精确**收集器确切知道哪些字是指针：编译器给出栈图，或者由库掌握 Handle。它能搬对象，因为它能更新每一个指针。
- **保守**收集器把看起来像指向堆的字都当作指针，通常用在缺少类型信息的栈上。被这种字指着的对象不能搬，因为那个字也许其实
  是个整数。

## 搬还是不搬

搬对象（复制、压缩、疏散）消除碎片、允许递增分配，但地址会变。持有地址的东西都得更新，收集器不知道的地方不能跨回收保存
裸地址。不搬的收集器嵌入起来简单得多，尤其是在到处是裸指针的 C++ 里。

## 析构与弱引用

- **析构函数**（finalizer）在收集器释放对象时运行：关文件、放锁、释放本地内存。什么时候运行由收集器决定，而且没有固定顺序，
  所以析构不能依赖其他被回收的对象。
- **弱引用**指着一个对象却不让它存活。回收之后，它要么仍指着那个对象，要么被清空。缓存和观察者列表用得到它。

## 怎么评价一个收集器

| 指标 | 问题 |
| --- | --- |
| **吞吐量** | 多大比例的时间花在程序本身而不是收集器上？ |
| **延迟** | 停顿多长、多频繁？ |
| **内存占用** | 除了活数据，还要多少内存？ |
| **对 mutator 的开销** | 屏障和分配让程序付出多少？ |
| **可扩展性** | 分配和回收能不能用上所有核？ |

没有哪种设计五项全赢。接下来几章里的每个收集器，都在它们之间做了不同的取舍。
