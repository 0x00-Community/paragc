# Far 引用与一起回收

一个进程里可以有好几个私有堆：一个 isolate 一个，或者一个子系统一个。`Far<'a, B>` 让一个堆里的对象直接指向另一个堆里的
对象，不复制，也不经过间接层。

## 建立与读取

```rust
// 同时在两个堆的 mutate 里
let far = Far::new(&holder_m, &target_m, target_gc);
let holder = holder_m.alloc(Holder { far });
// 之后读取要目标堆的 Mutator
let t = holder.far.get(&target_m);
```

- `Far` 带的是**持有方**堆的品牌，所以只能存在那个堆的对象里。
- 读取要**目标**堆的 `Mutator`。手里有这个 mutator，就证明目标堆是打开的，而且它此刻没有在回收。
- `Far` 建好后不变。要改指向，把它放进 `Slot` 后面的对象里，换掉那个对象。

## 入口：目标堆怎么看它

建立 `Far` 时在目标堆的根表里领一个槽，槽里还记着持有方堆。持有 `Far` 的对象被析构时（清扫或引用计数释放），归还这个槽。

- **单独回收目标堆**时，这些入口当根。年轻回收、引用计数、并发标记都不需要额外处理。
- **入口不搬。** 疏散回收开始标记之前，入口目标所在的块退出疏散，改当搬入目标。所以 `Far` 永远不需要改写。

## 跨堆的环：`collect_group`

环 A → B → A 在单独回收 A、单独回收 B 时都活着，因为两边在对方那里都是入口根。`Heap::collect_group(&mut [&mut Heap])`
（跨堆用 `CrossHeap::collect_group`）把几个堆放在一起回收：

1. 组内持有的入口不当根；
2. 每个堆从自己的根出发标记；
3. 追踪到的 `Far` 把目标交给目标堆，用那个堆的纪元标灰；
4. 各堆轮流标，直到没有一个堆还有灰对象；
5. 组内持有、目标没标到的入口属于已死的持有方，清空，免得之后的回收从已释放的对象开始标。

一起回收不疏散。

## 析构顺序

`Far` 持有目标堆根表的 `Arc`，所以先析构目标堆、后析构持有方也是安全的。目标堆没了就拿不到它的 mutator，`get` 也就无从调用。
