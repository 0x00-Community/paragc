# JVM 的收集器

垃圾回收是在 Java 虚拟机上实现工业化的。JVM 跑大量线程、分配速率极高，既要服务追求吞吐量的批处理，也要服务追求短停顿的
服务器。HotSpot（OpenJDK 的 JVM）没有只给一个收集器，而是提供了好几个，用命令行开关选择。合起来看，它们展示了整个设计空间。

## 共用的机制

| 机制 | 是什么 |
| --- | --- |
| **精确的根** | JIT 输出栈图；在安全点上，每个栈上的每个指针都已知 |
| **安全点** | 编译后的代码在循环回边和方法返回处轮询；回收时让所有线程停在安全点上 |
| **TLAB** | 每个线程在年轻代里自己的线程本地分配缓冲中递增分配 |
| **卡表** | 老年代按 512 字节分成卡；指针写进某张卡时写屏障把它标脏，年轻回收只扫脏卡 |
| **分代** | 年轻代（Eden + 两个 survivor 区，复制式）和老年代 |

## Serial

一个线程做全部工作，所有 mutator 停下。年轻代复制（Eden 和一个 survivor 复制到另一个 survivor 或老年代），老年代标记-压缩。
它适合小堆和单核机器，在 CPU 很少的容器里也还在用。

## Parallel（吞吐量收集器）

算法和 Serial 相同，但停顿中用上所有核，靠工作窃取分配任务。总吞吐量最好，代价是停顿随堆增大而变长。JDK 8 之前它是缺省收集器。

## CMS：并发标记-清扫

CMS（JDK 1.4）与程序**并发**地标记老年代，用增量更新式写屏障，只在开始（初始标记）和结束（重新标记）时短暂停顿，然后并发清扫。
它从不压缩老年代，所以受碎片困扰，分配失败时不得不退回一次长时间的完整回收。JDK 9 弃用，JDK 14 移除。

## G1：Garbage First

G1（JDK 6u14 实验，JDK 9 起缺省）把堆分成大小相等的**区域**（1–32 MiB）。

- 区域按需充当 Eden、survivor 或老年代；巨型对象占一串区域。
- 每个区域有一个记录外来指针的**记忆集**，所以任意一组区域都可以单独疏散。
- 标记是并发的，用**开始时快照**（SATB）屏障。
- 每次停顿疏散一个**回收集**：全部年轻区域，加上垃圾最多的老区域（名字由此而来），数量按**停顿时间目标**
  （`-XX:MaxGCPauseMillis`，缺省 200 ms）挑选。
- 压缩靠疏散逐步完成，碎片得到控制。

G1 在吞吐量和延迟之间取平衡，是大多数负载的缺省选择。

## ZGC

ZGC（JDK 11 实验，JDK 15 正式，JDK 21 起分代）的目标是停顿不到一毫秒，与堆大小无关，堆可以到数 TB。

- **染色指针**：每个 64 位引用里有几位元数据，记录它的标记与重定位状态。
- **读屏障**（load barrier）：每次从堆里读出指针都要检查。指针过期时，屏障当场修正它：找到或生成搬动后的副本。
- 标记、重定位、更新引用全部**并发**。停顿只处理根，长短与堆大小无关。

## Shenandoah

Shenandoah（Red Hat，JDK 12）同样与程序**并发**地疏散。它起初用 Brooks 转发指针（每个对象多一个字，指向它的当前副本），后来
改成和 ZGC 类似的读屏障。最近的版本也支持分代了。

## Epsilon

Epsilon（JDK 11）只分配、从不回收。它用于性能测试和极短命的程序。

## JVM 带来的启示

- 没有唯一最好的收集器；吞吐量、延迟、内存占用往不同方向拉。
- 分代、TLAB、卡表、记忆集是标准工具箱。
- 短停顿需要**并发搬动**，而并发搬动需要每次读指针都过读屏障。JIT 负担得起，因为每次访问都是它编译出来的。

paragc 借用了这个工具箱：TLAB 式的缓冲、记忆集、SATB 标记、并行工作窃取。它不借用读屏障。它是一个库，不是 JIT，没法在每次
读指针时插桩，所以只在 mutator 停下时才搬对象。
