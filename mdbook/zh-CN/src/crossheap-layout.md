# 地址空间与文件布局

## 地址区与窗口

`CrossHeapSpace::reserve` 占住的是一段**地址**，不是内存（`PROT_NONE` + `MAP_NORESERVE`）：

- 64 个窗口 × 16 GiB = 1 TiB，按自身大小对齐；
- 编号为 *k* 的跨堆永远映射在第 *k* 个窗口；
- 进程只映射它打开了的堆。

跨堆里的指针是**相对地址区起点的偏移**，所以同一个值在每个进程里都指向同一个对象，跨堆也一样。起点由区内任意地址抹掉
低位得到。

### 固定地址区

`CrossHeapSpace::reserve_fixed` 用 `MAP_FIXED_NOREPLACE` 把地址区放在 `FIXED_BASE` = 64 TiB。这样做的进程都把堆 *k* 映射在
同一个绝对地址上，所以跨堆对象里的普通绝对指针（`ScopeLocal`、`Slot`）在每个进程里都对。晋升就依赖这一点（见[晋升](promotion.md)）。
一个进程同一时间只能占一次固定地址区。

## 窗口内部

每一部分都在固定偏移，任何进程不用跟任何指针就能找到：

```text
偏移 0        超级块（一页）：身份、主人、计数器、各个栈头；挂接表在 1024 处
              类型表（1024 项：类型键 → 类型号、指针图位置）
              指针图（64K 个偏移）
              入口表（窗口每 16 KiB 一项）
              块状态表（每块的状态）
              块区（每块 32 KiB，从游标往后发）
```

超级块里有魔数（`paragcP5`）、主人、随机的化身号、`persist` 和 `dead` 标志、信箱头、来信计数、`owner_only` 标志，以及每
部分已经延长到哪里。

## 从空开始，用到才长

- 新堆的文件只有一页，就是超级块。
- 每部分第一次用到时用 `fallocate` 延长。`fallocate` 只会让文件变长，所以线程、进程之间抢着延长也安全。
- 在 tmpfs 上，`fallocate` 立刻占内存，所以内存用量就是文件长度；窗口的其余部分不占任何东西。
- 进程进 `scope` 时，拿自己映射的长度和超级块比，不够就补映射：平时只是一次比较，不走系统调用。

## 把内存还回去

清扫把空块留作备用，留的数量不超过上次回收以来分配的量，其余的打洞：

- 文件堆：`fallocate(PUNCH_HOLE | KEEP_SIZE)`；
- 匿名堆：`madvise(MADV_REMOVE)`。

相邻的一串块一次打掉。全零的块元数据就是一个合法的空块，所以打过洞的块仍在空闲栈上，和别的块一样复用。
`CrossHeap::shrink` 一个备用块都不留。

## 打开一个堆

| 调用 | 用途 |
| --- | --- |
| `space.create(path, threads)` | 在文件里新建一个堆；堆号在文件所在目录里领 |
| `space.create_anonymous(threads)` | 新建一个没有文件的堆（匿名共享内存），只能在本进程里用；用于测试、Miri 和 isolate 自用的老年代 |
| `space.open(path, threads)` | 按路径打开已有的堆 |
| `space.open_fd(fd, threads)` | 用经 Unix socket（`SCM_RIGHTS`）传来的文件描述符打开已有的堆，不需要路径 |
| `heap.fd()` | 要传出去的描述符（只有文件堆有） |
