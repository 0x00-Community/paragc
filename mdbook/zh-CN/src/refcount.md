# 引用计数

老对象带一个小引用计数。大部分老垃圾靠计数在后台释放，完整追踪隔几轮才做一次，专门收环和计数溢出的对象。做法照
LXR（Zhao、Blackburn、McKinley，2022）的第一到第三期。

## 计什么

RC(x) 是**老**对象指向 x 的边数。年轻对象发出的边，等它被晋升时再计。

计数放在对象头的 info 字里：

- 6 位，到最大值后粘住不变；
- 一个奇偶位。全停的完整回收翻转它，并在标记时把每条边精确地重算一遍；奇偶不对的计数属于上一代，从 1 重新开始。

## 维护计数

`Slot` 是两个字：值，和它上次计数时的值。

1. 老对象的槽在一轮里第一次被写时记下来。
2. 年轻回收结算它：新值 +1，上次计的值 −1。
3. 根延迟计数：每个当前的根 +1，上一轮的根 −1。
4. 所有加完了才做减。

老对象减到 0 时：

- 它的边逐个减一；
- 执行析构；
- 清掉起点位。

然后重算受影响的块的行。

## 后台释放

停顿（`finish_young`）里只结算加法，把减法推进队列。`collect_young` = `finish_young` + `sweep_concurrently`。在线程池上：

- 工人弹出减法；
- 谁把计数减到 0，谁就析构对象、清起点位、为它的边排减法，并把块记为脏；
- 计数为 0 的对象没有被计过的引用，而每个根和每个晋升的年轻对象都计过数，所以 mutator 不可能碰到它们。

脏块在下一次停顿开始时，根据剩下的老对象重算行。每次回收都先把挂着的减法做完，免得重算计数时在它们下面翻转奇偶位。

## 环和弱引用目标

- 环永远减不到 0，由定期的完整回收收掉。
- 有弱引用的对象计数被粘住。释放在后台进行，来不及先清弱引用，所以这种对象只能由追踪释放。

## 单个工人

只有一个标记工人时没人碰计数，重算就用普通的读写，不用带锁的原子读改写。
