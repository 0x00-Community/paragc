# paragc

Rust 的并行垃圾回收器。[English](README.md)

- **标记-区域堆（Immix 式）**：32 KiB 的块切成 256 B 的行；小对象碰撞分配进连续空行，超过 8 KiB 的单独分配。对象不移动。
- **多个 mutator 同时用**：`Heap::mutate(&self)` 可以在任意多个线程上同时调用；各自在自己的分配缓冲（`Tlab`）里碰撞分配，
  整块地领用（一次原子操作）。全程无锁。
- **并行回收**：标记多线程、工作窃取（每个工人一个 Chase–Lev 双端队列）；清扫（含析构）按块分给同一批线程。
- **借用即独占**：`Heap::collect(&mut self)` 不可能和 `mutate` 重叠，不需要安全点协议；`Gc<'gc, T>` 带品牌，逃不出 `mutate` 的闭包。
- 只支持 `std`。

## 设计

| 部分 | 做法 |
|---|---|
| 块 | 按 32 KiB 对齐，对象地址抹低位就是块起点；块头是行标记（每行一个 `u32` 纪元）和对象起点位图（每 8 字节一位） |
| 分配 | 分配缓冲拿着一个块，在「行标记 ≠ 当前纪元」的连续空行里碰撞；放不下找下一个空洞，块用完了从「有空行的块」→「全空的块」→ 新块依次领 |
| 对象头 | 24 字节：追踪函数、析构函数、标记纪元（原子）、粒度数（最高位 = 大对象） |
| 标记 | 根先轮流分给各工人；`swap(纪元)` 拿到旧值 ≠ 纪元的那个线程负责：写行标记、压进自己的队列（没有边的类型不压） |
| 结束判定 | 自己的队列空、也偷不到 ⇒ 空闲计数 +1，边等边偷；空闲计数 = 工人数 ⇒ 结束 |
| 清扫 | 工人按批领块：按起点位图逐个看对象，没标上本轮纪元的析构、清位；再按行标记把块分成 全空 / 有空行 / 满 |
| 根 | `Root<B>` 句柄占根表一个槽；根表只追加，空槽号在回收时整理成只读数组、mutate 期间原子游标领取 |
| 分配缓冲过期 | 缓冲记着（堆, 回收次数），回收过就整个作废（它的块已被重新分类） |

无锁基础件（Chase–Lev 双端队列、只追加分段向量、库存）来自 [j8lockfree](https://crates.io/crates/j8lockfree)。

## 规则

- 堆里的类型实现 `Trace`（用 `#[derive(Trace)]`），而且必须 `Send + Sync`：对象可能在任何线程上被读、在回收线程上被追踪和析构。
  要改的边放 `Slot<'gc, T>`（原子指针）。
- 有 `Gc` 字段的类型不许实现 `Drop`：析构顺序不定，`Drop` 里可能碰到已经析构的对象。derive 会检查，`#[trace(unsafe_drop)]` 关掉检查。
- 只有从 `Root` 可达的对象能活过回收。`Root<B>` 是强引用句柄，可以存在任何地方、跨线程传。
- 对象数据的对齐不能超过 8 字节（编译期检查）。

## 路线

0.1：暂停式、不移动。之后：

1. 并发标记：`Slot` 写入加初始快照（SATB）屏障，mutator 不再等回收
2. 稀疏块的机会式疏散（Immix defrag）
3. 年轻对象引用计数（LXR 式）：新对象死了立刻回收行，追踪只负责环与老对象

## 测试

逐条跑：`cargo test --test gc -- --exact <名字>`。

Miri（Stacked / Tree Borrows 都要过，测试在 `cfg(miri)` 下自动缩规模）：

```sh
MIRIFLAGS="-Zmiri-permissive-provenance" cargo +nightly miri test --test gc -- --exact <名字>
MIRIFLAGS="-Zmiri-permissive-provenance -Zmiri-tree-borrows" cargo +nightly miri test --test gc -- --exact <名字>
```

`eight_threads_eight_heaps_crossed`：8 线程 × 8 堆，跨堆持有根（链头挂着别的堆上的链）、跨线程检查与释放、
全部堆并行回收的同时另一个线程释放根、大对象与节点成环；最后反复回收直到析构数 = 创建数。Miri 下缩成 4 × 4。
